1) EXECUTIVE SUMMARY
--------------------------------------------------------------------------------

What is PharmLMS?
  A web-based learning management system for pharmacy and clinical training.
  It connects three audiences in one platform:
    • Students — discover courses, learn with progress and assessments, and
      earn recognition (badges).
    • Mentors (instructors) — build structured courses, manage curriculum,
      communicate with learners, and run mentor meetings.
    • Administrators — oversee the catalog, review and approve courses before
      they go live, manage users, and configure achievements (badges).

Value proposition
  • Single place for curriculum, engagement, and governance.
  • Role-based access so each group sees the right tools and data.
  • Built to scale: modern web stack, structured data model, and clear paths
    for future analytics and enterprise features.

Opening line (optional)
  "Today I will walk you through what we've built, how each role uses it, and
   how the technology supports security and growth — then we will do a short
   live demo in that same order."

3) END-TO-END PRODUCT WALKTHROUGH BY ROLE
--------------------------------------------------------------------------------

3.1 Student journey
  Entry
    • Land on the public home page, choose a portal, or go straight to sign-in.
    • Sign up or sign in (email and password, or Google where configured).

  Core loop
    • Browse the course catalog, open a course, and enroll.
    • Open a course: lessons load in a structured way; progress is tracked.
    • Use learning aids where enabled (for example, AI quiz practice from
      course content, depending on configuration).

  Beyond lessons
    • Book or join mentor meetings (where availability and workflow allow).
    • View achievements and badges on a dedicated page as milestones are met.
  • Complete a course and download a Pharm LMS digital certificate (print to
    PDF from the browser).

  What to say
    "For learners, the product is the full loop from first login to completion
     and recognition — not just video or text, but also engagement, mentoring,
     proof of progress through badges, and a printable certificate when they
     finish."


3.2 Mentor (instructor) journey
  Entry
    • Sign in as a mentor, land on the mentor area (performance and tools).

  Create a new course
    • Simplified multi-step onboarding: working title, category, and time
      commitment, then the system creates a draft course.
    • Branding in the flow is PharmLms (not generic placeholder labels).

  Build the curriculum
    • Curriculum editor: sections, order (drag and drop), lessons as video or
      article, add quizzes and assignment-style items to a section.
    • While work is saving, controls lock so the mentor cannot stack conflicting
      actions — this is intentional for a stable experience.

  Operate
    • Communicate, manage meeting-related workflows, and track how the course
      is doing as you iterate.

  What to say
    "Mentors get a studio-style workflow: draft first, then build structure,
     then add rich content and assessments, with safeguards while saves run."


3.3 Administrator journey
  Entry
    • Admin signs in with credentials (admin account is not self-service via
      Google in the current design; that reduces accidental privilege creation).

  Govern
    • Admin dashboard: KPIs and navigation to operational areas — for example
      pending review, published courses, total enrollments, and badges
      activity (where implemented on the dashboard).

  Course quality
    • Review courses submitted for approval; approve, reject, or request
      changes according to your process.

  Program design
    • Manage the badge catalog and see reference documentation for what each
      rule type means, so the program is transparent to staff.

  What to say
    "Admins are the control tower: they protect quality, visibility, and how
     recognition rules work, without having to be in the day-to-day authoring."

4) TECHNICAL ARCHITECTURE (CLIENT-FRIENDLY)
--------------------------------------------------------------------------------

How to say it in the room
  "The application is a modern web product: fast pages, clear separation
   between the interface and the database, and standard patterns for sign-in
   and file storage. That means maintainability, security you can reason about,
   and a path to grow."

Stack (one sentence each)
  • Web application: Next.js (App Router) — server and client parts work
    together for performance and security.
  • Data: PostgreSQL with Prisma — the schema models courses, people, progress,
    meetings, and badges in one consistent structure.
  • Sign-in: NextAuth — email and password, plus optional Google for students
    and mentors when configured. Roles are stored in the database and applied on
    every request (role-based access).
  • Media: object storage (S3-compatible, e.g. Cloudflare R2) for lesson
    assets, with a controlled way to read and write files.
  • APIs: route handlers for courses, curriculum, student streaming, meetings,
    and AI-assisted features, so the UI stays thin and testable.

Why clients care
  • You can hand this to a technical team: it is a standard, hireable stack.
  • You can add reporting, single sign-on, or integrations without rebuilding
    the product from scratch.

5) DELIVERED HIGHLIGHTS (RECENT / NOTABLE)
--------------------------------------------------------------------------------

5.1 Badges and achievements
  • Configurable rules (for example: first enrollment, lesson milestones, quiz
    behavior, streaks, mentor meetings). Students see what they have earned
    and what is still to unlock.
  • Admins can manage badges and see a rules reference for transparency.

5.2 Meetings
  • Mentors and students can work within a meeting workflow (requests,
    responses, and completion) so training is not only self-paced.

5.3 Curriculum experience
  • The curriculum editor supports section ordering, multiple content types, and
    items such as quizzes and assignments.
  • Saving and reordering are guarded so users do not trigger overlapping
    writes by accident while a save is in progress.

5.4 Sign-in
  • Email and password for all applicable roles; Google OAuth for students and
    mentors when environment variables are set. Admin sign-in is credential
    based in the current design.
  • Fresh start option: environment-driven seeding for a single admin and
    default badge definitions, with end-user accounts created through sign-up.

5.5 Mentor new-course flow
  • Simplified to three user-facing steps after removing an unnecessary
    "type of product" step; product naming shows PharmLms in the flow.

5.6 Paid courses and multi-currency
  • Paystack checkout for priced courses; tutor wallet and admin withdrawal
    approval.
  • International learners can see USD prices; Nigeria sees NGN; Paystack
    charges in NGN (MVP).

5.7 Digital certificates
  • On course completion, students receive a branded Pharm LMS certificate
    (student name, course, hours, instructor, date, certificate ID).
  • View and print from the course player completion area.

7) RISK HANDLING AND OBJECTIONS
--------------------------------------------------------------------------------

Security
  • Sign-in is industry-standard. Roles are enforced server-side.
  • Admin is not self-created via public OAuth, reducing the risk of accidental
    admin creation in production.
  • Media and lesson access should be demonstrated as gated by rules in the
    app (enrollment and course state), not "public by default."

Data and privacy
  • Personal data is stored in the application database; object storage holds
    media. Your deployment can follow your data residency needs.

Stability
  • Curriculum and upload flows are written to avoid concurrent conflicting
    actions during saves.

Scalability
  • The architecture separates UI, API, and database, which is the right base
    for load growth and monitoring.
